# 画面のデザインの方針

画面を作る人と、AI エージェントに向けた、見た目と使い勝手の決まりの要約です。値の出どころと理由は、[設計書の 11 章](design/11-screens.md) にあります。

## 基本

- スマホを基準に作り、同じ画面を PC では配置だけ変える。端末ごとに別の画面は作らない
- 画面幅の区切りは 840px の 1 か所 (`apps/web/src/lib/styles/_breakpoints.scss`)。840px 未満は画面下部のタブ、以上は左のメニュー
- 文字は LINE Seed JP。LINE Seed JP にない字は Noto Sans JP で補う (どちらも `@fontsource/*` を自前で配る。太さは 400 と 700)。読み込む前は OS の標準フォント
- ライトとダークの両方で、すべての画面を確かめる

## 色

大学のロゴの赤を基調にした SMUI (Material Design) のテーマ。画面の色は、CSS のカスタムプロパティ (`--fm-*`) を通して使い、値を直接書かない。

| 役割               | ライト    | ダーク    |
| ------------------ | --------- | --------- |
| primary            | `#9d2126` | `#d6999e` |
| secondary (リンク) | `#3d6cbc` | `#9fb8e6` |
| 本文               | `#333333` | `#e6e1e1` |
| 背景               | `#ffffff` | `#141212` |

- 本文のコントラストは WCAG AA (4.5:1 以上)
- 休講と主色がどちらも赤なので、状態は色だけで伝えない。休講は取り消し線と「休講」、補講は「補講」、教室変更は「教室変更」と新しい教室を添える

## 部品と SCSS

- スタイルは、すべて `<style lang="scss">`。150 行を超えるものは、同じ場所の `.scss` (`+page.svelte` なら `page.scss`、部品なら `部品名.scss`) に分け、`<style>` からは `@use './page';` のように読む。スコープは同じように効く
- 2 つ以上の画面に同じ形で書くものは、`apps/web/src/lib/styles/` の mixin を使う
  - `_mixins.scss`: 並べ方 (`stack()`、`wrap-row()`、`cluster()`)
  - `_forms.scss`: チェックボックスの行 (`choice-row()`)、縦に並べたフォーム (`column()`)
  - `_surfaces.scss`: 線で囲んだ入れ物 (`outlined()`)、薄い背景の入れ物 (`muted-panel`)、秘密の値の枠 (`secret-box`)
  - `_text.scss`: 補足の小さな文字 (`muted()`)、一覧の 1 件の名前 (`item-title`)、状態の札 (`badge`)
  - `_touch.scss`: 押せる高さのリンク (`target()`)、`<details>` の見出し (`summary`)
  - `_chrome.scss`、`_header-action.scss`: レイアウトのロゴとフッター、上のバーの操作
- ページ本文の幅は `.page` (既定 44rem)。広い表だけ `.page-w-<rem>` で広げる
- SMUI にある部品は SMUI を使う。`@smui/<部品>` を import すれば、その部品の CSS は自動で読まれる。SMUI の見た目を変えるときは `smui-overrides.scss` に書く (CSS のレイヤーで、部品より強くなる)
- チェックボックスとラジオボタンは `CheckboxField` と `RadioField` (SMUI の部品とラベルを包んだもの)。フォームはブラウザの標準のまま送る。ラジオの組は、同じ変数を `bind:group` (変えないなら `group`) に渡す
- 入力欄は `TextField` (SMUI の outlined の欄とラベルを包んだもの)。`label` に名前を渡し、`name` や `maxlength` などは中の input に付くので、フォームはブラウザの標準のまま送る。複数行は `textarea`、読むだけでコピーしてもらう欄は `readonly` と `selectOnFocus`
  - ラベルは欄の枠に乗り、長いと切れるので短くする。説明は欄の外の文にし、`aria-describedby` で欄と結ぶ
  - 必須の印 (`*`) は出さない。任意の欄のラベルに「(任意)」と書く
  - ファイルの欄は SMUI に部品がないので、ブラウザの標準のまま
- 選択欄は `SelectField`。スマホで OS の選択の画面を出すため、ブラウザの `<select>` のまま、枠とラベルを `TextField` と同じ見た目にする。`label` に名前を渡し、`<option>` を中に書く。`name` などは `<select>` に付く
- 管理画面の表は SMUI の data-table (`@smui/data-table`)。見た目は `smui-overrides.scss` でそろえ、日時や回数の列は `Cell` に `class="numeric"` を付けて折り返さない。週の時間割の表は、見出しの固定や 1 日ずつの横送りなど独自の作りが多いので、SMUI にしない
- 中身の表示を替えるものは SMUI のタブ (`@smui/tab-bar`、科目の画面、バスの平日と休日)、見せ方を選ぶものは SMUI の切り替えのボタン (`@smui/segmented-button`、週の時間割の見せ方、取り込みの方法)
- 補助の文字は `.muted`、画面の外に隠す文字は `.visually-hidden`
- 破壊的な操作の前の確認は、フォームに `use:confirmSubmit={'…よろしいですか?'}` を付ける。最上位のレイアウトの SMUI のダイアログ (`ConfirmDialog`) が出て、「続ける」で送る
- フォームの結果は `FormNotice` に渡す。失敗の理由は画面の中に残し、うまくいった知らせは画面の下に短く出す (SMUI の snackbar、`NotifySnackbar`)。スマホでは下のタブの上に出す

## 操作

- キーボードだけで、すべての操作ができる。フォーカスの位置が見える。Tab の順番は見た目の順番
- 押せる範囲の大きさ (48px 以上) と位置は、表示や状態が変わっても保つ。ボタンや欄が動かない
- hover でしか出ない情報は作らない
- 外のサイトへのリンクは、新しいタブで開き、`rel="noopener noreferrer"` を付ける

## 文言

画面の文言は、日本語で、全角の記号は ！と？以外は使わず、設計書の番号や、設計書を指す言い方は書かない。

画面の名前は 1 つに決め、どこでも同じ名前で呼ぶ。

- その画面へのカードやリンク、パンくずの現在地、見出し (`h1`)、ページのタイトル (`<title>`) は、同じ名前にする。見出しには、年度や日付のような、その場で変わる値を足してよい
- 「履修科目を登録する」のように、操作を表すリンクは、画面の名前でなくてよい
- 画面の名前を変えるときは、古い名前で検索し、ほかの画面の文言、テスト、文書の呼び方もそろえる
