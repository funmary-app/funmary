# 12. カレンダー連携

設定の「カレンダーの購読」で、購読用の URL `https://<ドメイン>/cal/<トークン>.ics` を発行します。PC で設定しながら、スマホに登録できるように、同じ URL の QR コードも出します。URL は、再発行と無効化ができます。

## 12.1 仕組み

- ICS は、Hono がリクエストのたびに ical.js で組み立てます。内容が同じなら、ETag のミドルウェアで `304 Not Modified` を返します
- トークンは、32 バイトの乱数で、DB にはハッシュだけを保存します。URL にトークンが入るので、共有のキャッシュには残させず (`Cache-Control: private`)、検索にも載せません (`X-Robots-Tag: noindex`)
- 同じトークンで取りに来られる回数は、15 分に 60 回までです
- 持ち主が、利用規約への同意を待っている間は、予定を返さず、403 と説明を返します

## 12.2 予定の書き方

- 期間は、2 週間前から、半年先までです
- 各授業の UID は、科目、日付、時限から作ります。更新しても、予定が重複しません
- 休講の授業は、消さずに `STATUS:CANCELLED` を付け、タイトルの先頭に `[休講]` を付けます。`STATUS` を表示しないカレンダーのアプリがあるので、タイトルでも分かるようにします。補講には `[補講]`、教室変更には `[教室変更]` を付けます
- 場所の欄に教室を、説明の欄に教員、授業の詳細画面の URL、シラバスの URL を入れます
- 利用者が足した予定と、時間割に加えたほかの人の予定も、同じ URL に入れます

## 12.3 限界と、通知での補い

カレンダーのアプリが ICS を取りに来る間隔は、アプリ次第で、Google カレンダーでは数時間から 1 日かかります。当日の休講は、ICS では間に合わないことがあるので、通知 (Discord、RSS、通知欄) で補います。Google カレンダーは、購読した ICS の通知の設定 (`VALARM`) を無視するので、授業前のリマインダーも、Funmary の通知で送る予定です。
