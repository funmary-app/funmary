# 10. データモデル

## 10.1 テーブル

SQLite に保存します。定義は `packages/db/src/schema.ts` に、マイグレーションは `packages/db/migrations/` にあります。マイグレーションは、列やテーブルを足す方向だけにして、1 つ前の版のアプリがそのまま動くようにします。

| 区分             | テーブル                                                     | 内容                                                                                                                  |
| ---------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| アカウント       | `users`、`sessions`、`user_permissions`                      | 利用者 (同意した規約の版を含む)、ログイン中のセッション、利用者ごとの権限                                             |
|                  | `invite_codes`                                               | 招待コード。コードはハッシュで保存し、使用回数、期限、発行者、メモを持つ                                              |
|                  | `terms_acceptances`                                          | 利用規約への同意の履歴                                                                                                |
|                  | `test_accounts`                                              | 管理者が用意するテストアカウント                                                                                      |
| 授業             | `subjects`                                                   | 科目。年度とシラバスの番号の組で区別する。シラバスにない授業として足した科目も、公開範囲つきで入る                    |
|                  | `timetable_slots`                                            | 科目ごとの、共有の曜日、時限、教室                                                                                    |
|                  | `course_registrations`                                       | 利用者の履修科目                                                                                                      |
|                  | `personal_timetable_slots`                                   | 利用者だけに見える、曜日と時限の書き換え。共有のコマは変えない                                                        |
|                  | `slot_submissions`                                           | 曜日と時限を、利用者が提出し、管理者が確認するための待ち行列                                                          |
| 休講など         | `class_changes`                                              | 休講、補講、教室変更。3 種類を 1 つの表にまとめる                                                                     |
|                  | `unmatched_lessons`                                          | 科目と照合できなかった授業名                                                                                          |
| 暦               | `academic_terms`、`academic_days`、`holidays`                | 学期の期間、振替授業日と全学の休講日、祝日。どれも、値の出どころ (自動取得、手入力、推定) を記録する                  |
| 予定             | `user_events`、`event_subscriptions`、`access_grants`        | 利用者の予定、ほかの人の予定を時間割に加えた記録、メールアドレスで指定した公開                                        |
| 購読と API       | `feed_tokens`、`access_tokens`                               | カレンダーと RSS の URL のトークン、公開 API と MCP のアクセストークン (名前、範囲、期限)。どちらもハッシュで保存する |
|                  | `oauth_clients`、`oauth_codes`、`oauth_refresh_tokens`       | MCP の認可 (OAuth 2.1) で、登録されたクライアント、認可コード、リフレッシュトークン                                   |
| 通知             | `notifications`                                              | 通知欄の中身。利用者ごとに 1 行                                                                                       |
|                  | `channels`、`deliveries`                                     | 利用者ごとの通知の送り先 (Webhook の URL や署名の鍵は暗号化する)、送った記録 (再送の管理)                             |
|                  | `discord_links`、`daily_digest_settings`                     | Discord との連携 (トークンは暗号化する)、毎日のまとめの設定                                                           |
| 運用             | `source_status`、`job_runs`、`settings`、`audit_log_entries` | 取得元ごとの状態、定期処理の実行記録、管理画面で変える設定、管理操作の監査記録                                        |
| まだ使っていない | `absences`、`shares`、`hope_calendars`、`hope_events`        | 欠席の記録、時間割の共有リンク、HOPE の課題。テーブルだけあり、機能は予定                                             |

利用者の持ち物は、外部キーの `ON DELETE CASCADE` で、利用者を消すとまとめて消えます (退会の仕組み)。足した科目や監査記録のように、利用者より長く残したいものは `SET NULL` で、持ち主の記録だけが外れます。

### SQLite の設定

WAL モード、`synchronous=NORMAL`、`busy_timeout=5000`、外部キーを有効にします。書き込むのは、このプロセスだけなので、書き込みの競合は起きにくくなっています。マイグレーションの前には、自動でバックアップを取ります。

## 10.2 時間割の展開は 1 つの関数にまとめる

授業の予定を作る処理は、`packages/core` の `expandTimetable()` 1 つにまとめます。受け取るのは次の 5 つで、授業の予定の配列を返します。

- 履修科目と、そのコマ
- 学期の期間
- 祝日と、全学の休講日
- 振替授業日
- 休講、補講、教室変更の一覧

処理は 3 段階です。

1. 対象期間の日付ごとに、曜日を決める。振替授業日なら、指定された曜日として扱い、祝日と全学の休講日なら、授業はない
2. 各科目のコマから、曜日と学期が合うものを、予定にする
3. 休講の授業には印を付け、補講は予定として足し、教室変更は教室を書き換える

同じ日、同じ時限、同じ科目に複数の情報が重なったときは、休講、補講、教室変更、ふつうの授業の順に優先します。補講の教室は、ポータルの補講の一覧にある教室名を使います。教室名がなければ、その科目のふだんの教室を仮に出し、仮であることを示します (`roomIsTentative`)。

科目の学期は、通年、前期、後期、1Q から 4Q、夏期集中、冬期集中を区別します。それぞれの期間は、[9 章](09-academic-year.md) の方法で、年度ごとに決めます。シラバスの「前期集中」は夏期集中に、「後期集中」は冬期集中にまとめます。開講期の欄が前期でも、授業名に「夏期集中」とあれば、夏期集中とします。

時間割の画面、授業の詳細、カレンダーの購読 (ICS)、公開 API、MCP、Discord のコマンド、毎日のまとめは、すべてこの関数の結果を使います。副作用がないので、学期の境目や振替授業日の扱いを、テストで網羅しやすくなっています。口ごとに答えが食い違わないよう、読み取りの形は `packages/api/src/reads/` に 1 つだけ置いています。

時限の時刻は、次の値を初期値にします。

| 時限 | 1          | 2           | 3           | 4           | 5           | 6           |
| ---- | ---------- | ----------- | ----------- | ----------- | ----------- | ----------- |
| 時刻 | 9:00-10:30 | 10:40-12:10 | 13:10-14:40 | 14:50-16:20 | 16:30-18:00 | 18:10-19:40 |

公式の資料が見つからなかったので、この値のまま使っています。管理画面で変えられるようにするのは、予定です。API の `/api/v1/periods` で、いまの値を読めます。
