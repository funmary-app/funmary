# 15. ライセンス

## 15.1 コードは、BSD-3-Clause と Apache-2.0 のデュアルライセンス

Funmary のコードは、利用者が、BSD-3-Clause と Apache-2.0 のどちらかを選べるデュアルライセンスです。SPDX の式では、`BSD-3-Clause OR Apache-2.0` と書きます。

2 つはどちらも制限が少なく、互いの弱みを補い合います。

| 観点 | BSD-3-Clause                                       | Apache-2.0                                                         |
| ---- | -------------------------------------------------- | ------------------------------------------------------------------ |
| 強み | 短く読みやすい。GPLv2 のプロジェクトにも取り込める | 特許の利用許諾が明記されている。受け取った貢献の扱いも、条文にある |
| 弱み | 特許について、何も書いていない                     | GPLv2 とは両立しない。条文が長い                                   |

両方を用意しておけば、利用者は、目的に合うほうを選べます。Rust などで広く使われている「MIT OR Apache-2.0」と同じ考え方で、MIT の位置に BSD-3-Clause を置きました。

SPDX の式では、`OR` と `AND` の意味が違います。Funmary が使うのは `OR` です。`AND` は、両方の条件を、同時に守ることを求めるので、選べる利点がなくなります。コードはすべて同じ作者 (と、貢献者) が書くので、`AND` を使う理由はありません。

ほかの組み合わせは、次の理由で見送りました。

- MIT: BSD-3-Clause とほぼ同じ内容なので、併用しても、選択肢が増えない
- GPL-3.0、AGPL-3.0: 改変版の公開を求めるので、手軽さを求める方向と逆になる

## 15.2 置き方

- リポジトリ直下の `LICENSE-BSD-3-CLAUSE` と `LICENSE-APACHE-2.0` に、それぞれの全文を置きます。本文は、SPDX の原文のままです。GitHub が、種類を判定できるようにするためです
- ルートと各パッケージの `package.json` の `license` には、`(BSD-3-Clause OR Apache-2.0)` と書きます
- README の末尾に、どちらかを選べることと、貢献されたコードも同じ 2 つのライセンスで受け取ることを書きます

## 15.3 ロゴとアイコンは、コードのライセンスの対象外

ロゴとアイコンは、コードに適用する 2 つのライセンスの対象外で、`LICENSE-ASSETS` に利用条件があります。セルフホストで、自分のロゴに差し替えられるよう、画像は `BRAND_DIR` に同じ名前で置けば、同梱のものより先に使われます ([セルフホストの手順](../self-hosting.md))。

## 15.4 同梱するライブラリのライセンス表示

本番のビルドには、多くのライブラリが入ります。MIT などのライセンスは、著作権表示を残すことを求めるので、リリースに、`THIRD_PARTY_LICENSES.txt` (ビルド時に、入ったパッケージのライセンス文を集めて作る) と、`LICENSE` の本文を入れます。画面でも、`/license` と `/third-party-licenses` で読めます。

## 15.5 大学との関係

Funmary は、公立はこだて未来大学とは無関係の、非公式のアプリです。大学のロゴや校章は、画面にもアイコンにも使いません。画面の下部と README に、非公式であることを書いています。
