# 14. セキュリティ

リポジトリは公開します。コードを読まれても安全であること、そして、秘密がコードや履歴に入らないことが前提です。脆弱性を見つけたときの報告の方法は、[SECURITY.md](../../SECURITY.md) にあります。

## 14.1 秘密の扱い

| 対象                                                                                                         | 扱い                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Google の秘密情報、ポータルのパスワード、セッションの鍵、暗号化の鍵、Discord の Bot のトークンなど           | 環境変数のファイルに置く。手元の開発ではリポジトリのルートの `.env`、本番では `/etc/funmary/funmary.env`。どちらも、リポジトリには入れない (`.env.example` だけが入る) |
| Webhook の URL と署名の鍵、Discord 連携のトークン                                                            | AES-256-GCM で暗号化して DB に保存する                                                                                                                                 |
| カレンダーと RSS の URL のトークン、招待コード、公開 API と MCP のアクセストークン、OAuth のコードとトークン | 32 バイトの乱数を使う。DB には SHA-256 のハッシュだけを保存し、発行したときに 1 回だけ見せる                                                                           |
| ログ                                                                                                         | URL、トークン、メールアドレスを出さない。ログの出力の部品が、トークンの形の文字列を伏せる                                                                              |

- 環境変数のファイルと、実データを含む HTML は、`.gitignore` に入れます。CI では、gitleaks で、秘密情報の混入を検査します
- テストのデータには、実名、学籍番号、メールアドレスを入れません。保存したポータルの HTML をテストに使うときは、個人情報を伏せてから入れます

## 14.2 認証と、攻撃への備え

- ログインは、Google の OpenID Connect で、PKCE、state、nonce、ID トークンの署名を検証します。ドメインと `email_verified` は、サーバー側で確かめます ([7 章](07-accounts.md))
- セッションは、DB に保存し、ブラウザには HttpOnly の Cookie で ID だけを渡します。本番の Cookie は、`__Host-` を付けて、`Secure`、`Path=/`、ドメインなしを、ブラウザに強制させます
- **CSRF**: フォームの送信は、`Origin` ヘッダを、公開 URL と照らして断ります。SvelteKit 組み込みの検査の代わりに、`hooks.server.ts` で同じ検査を行っています。MCP のクライアントが、`Origin` なしで `form` を送る `/oauth/token` だけは、Cookie を使わない口なので、例外にしています
- 公開 API と MCP は、Cookie では認証しません (Bearer トークンだけ)。CORS も開けないので、ほかのサイトのブラウザから呼ぶ使い方は、想定しません
- カレンダーと RSS の購読、公開 API、OAuth の登録とトークンの口には、回数の制限を置きます
- 戻り先 (ログインや同意のあとに戻る URL) は、このサイトの中のパスだけを通します。外のサイトへは飛ばしません
- 共有に向いたページ、購読の URL には、`X-Robots-Tag: noindex` を付け、検索エンジンに載せません

## 14.3 外部から取り込む内容は、信用しない

大学のサイトの HTML、PDF、祝日の CSV、利用者が指定する Webhook の URL は、すべて、Funmary の管理の外にあります。

- HTML は、4 段の解析を通します ([8.5](08-data-fetching.md#85-html-の解析))。画面には、Svelte の通常の出力 (自動でエスケープされる) だけを使い、`{@html}` は使いません
- 外部の文字列をキーにする入れ物には、`Map` を使います (`__proto__` などを使った攻撃を避けるため)
- 外部の URL は、`https:` で、許可したホストのものだけを残します
- 利用者が指定する Webhook の URL は、サーバーの内側へ向かわないよう、通信の前に検査します ([13.3](13-notifications.md#133-discord-への通知))
- 外部のサイトへのリンクは、`target="_blank"` と `rel="noopener noreferrer"` を付けて、新しいタブで開きます

## 14.4 個人情報

- 学籍番号は、受け取りません。メールアドレスは、画面では、押すまで伏せます
- 退会すると、利用者のデータをすべて消します。自分のデータを、JSON で書き出すこともできます
- 規約とプライバシーポリシーが変わったときは、全員に、もう一度同意を求めます ([2 章](02-architecture.md#利用規約への同意))
