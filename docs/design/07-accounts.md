# 7. アカウントと招待コード

## 7.1 ログインは大学の Google アカウントに限る

- Google の OpenID Connect でログインします。手順は openid-client に任せ、PKCE、state、nonce、ID トークンの署名の検証を正しく行います。要求するスコープは `openid email profile` だけです
- 認可リクエストに `hd=fun.ac.jp` を付け、アカウント選択画面で大学のアカウントが選ばれやすくします
- 認可リクエストには `prompt=select_account` も付け、アカウント選択画面を毎回出します。付けないと、Google は前回のアカウントで自動で進みます。Funmary からログアウトしても Google のログインは残るので、別のアカウント (テストアカウントなど) に替えられなくなります
- `hd` は画面上のヒントにすぎません。コールバックでは、ID トークンの `hd` と `email_verified`、メールアドレスのドメインをサーバー側で確かめ、条件に合わなければアカウントを作りません。許可するドメインは `ALLOWED_EMAIL_DOMAINS` で変えられます (既定値は `fun.ac.jp`)
- セッションは DB に保存し、ブラウザには HttpOnly の Cookie でセッション ID だけを渡します。有効期限は 30 日で、DB にはセッション ID のハッシュだけを保存します
- Google のログインが一時的に使えないときも、ログイン済みの人は、セッションが切れるまで使い続けられます

## 7.2 新規登録は招待コード制を既定にする

`REGISTRATION` で、登録の方式を切り替えます。

| 値              | 登録できる人                         |
| --------------- | ------------------------------------ |
| `invite` (既定) | 招待コードを持っている人             |
| `open`          | 許可ドメインのアカウントを持つ人全員 |
| `closed`        | 誰も登録できない (既存の利用者だけ)  |

招待コードの流れは次のとおりです。

1. 発行できる人が、設定画面の招待コードの欄 (または管理用コマンド) で、招待コードを発行する。使用回数の上限、有効期限、メモ (誰に渡したか) を付けられる
2. 受け取った人が `/signup?code=...` を開く。コードが有効なら、コードを 10 分間だけ Cookie に保持して、Google のログインへ進む
3. ログインから戻ったら、ドメインとコードを確かめてアカウントを作る。コードの使用回数を 1 増やし、誰の招待で登録したかを記録する

### 招待コードを発行できる人

発行できる人は、管理画面の招待コードのページで、3 つのモードから選びます。値は DB の設定に置くので、再起動は要りません。

| モード            | 発行できる人                                              |
| ----------------- | --------------------------------------------------------- |
| 管理者のみ (既定) | 管理者                                                    |
| 許可したユーザー  | 管理者と、管理者が発行の権限 (`invite:create`) を付けた人 |
| 誰でも            | ログインしている全員                                      |

管理者でない人のコードは、1 回だけ使えて 30 日で期限が切れ、1 か月 (日本時間の暦の月) に発行できる数に上限があります (既定は 5 で、管理画面で変えられます)。管理者は、使用回数、期限、メモを決めて、上限なく発行できます。

権限は、利用者ごとの表 (`user_permissions`) に持ちます。ロールを増やすときは、ロールを権限の組として定義します。

管理画面では、招待した人とされた人の関係、コードごとの利用状況を一覧で見られます。問題のある利用者は停止できます。

## 7.2.1 テストアカウント

管理者は、設定の「テストアカウント」で、大学のアカウントでない Google のアカウント (メールアドレス) を足せます。足したアカウントは、ログインの画面の「テストアカウントでログイン」から入れます。

- 管理者ごとに持ち、1 人 5 個までです。大学のドメインのメールアドレスと、すでに利用者のメールアドレスは足せません
- ログインの判断では、そのメールアドレスだけ、ドメインと `hd` の検査と、登録の方式 (招待制、閉鎖) を問いません。メールアドレスの確認 (`email_verified`) と、停止は、ふつうどおり守ります
- 入口 (`/auth/google/test`) は、Google のアカウントの選択に `hd` の絞り込みを付けません。ふつうの入口から進んでも、テストアカウントなら入れます。用意していないアカウントは、どの入口でも断ります
- テストアカウントのデータは、管理者から引き継ぎません。空から始まります。必要なときだけ、管理者が「自分のデータを写す」で、自分の履修科目、曜日と時限の書き換え、予定を置き換えて写せます (予定は非公開にして写します)
- 消すと、そのアカウントの利用者と、持ち物もすべて消えます

## 7.3 ロールと退会

利用者のロールは、一般の利用者、モデレーター、管理者の 3 つです。

- `ADMIN_EMAILS` に書いたメールアドレスの利用者が、管理者になります。管理用コマンドでも、管理者にできます。`ADMIN_EMAILS` の人は、最初にログインできるように、登録の方式や招待コードを問いません
- モデレーターは、管理画面のうち、曜日と時限の確認待ちと監査ログだけを開けます。設定を変える画面は、管理者だけです
- 退会は、設定の「データの書き出しと退会」から、利用者が自分でできます。メールアドレスを打って確かめると、アカウントと持ち物 (履修、予定、通知、トークン、Discord 連携など) をすべて消します。自分だけが見られる足した科目も消し、公開した科目と監査記録は、持ち主の情報だけを外して残します。同じ画面で、自分のデータを JSON で書き出せます (トークンそのものや、Webhook の URL などの秘密は入れません)
